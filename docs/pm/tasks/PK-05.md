**补充（04:56Z，5747736773，自述）**：只把原 B 的 `norm_backward` 换成与 Torch 2.10 autograd 在 10 个归一化 primitive 用例上**逐位相同**的解析求导顺序（`norm.clamp_min(1e-12)` 之后的链式写法）、其余不动，21 个 clamp 用例仍有 8 个失败

**补充 2（05:05Z，5747774486，自述）——问题比「近 eps 行」宽，不能用范数区间当闸**：保留 literal A 与原解析 B，B1/T64/H1/HV2/K=V128、q/k 每行仅第一分量非零，8 个范数 `{1e-6, .03, .05, .1, .3, .5, 1, 2}` × do-only / dA_T-only 共 16 条记录，
6 过 10 败（`.5 / 1 / 2` 两种组合过，其余都在 dq 或 dk 上败）。例：范数 .03 / do-only 的 dq A↔B 相对 L2 1.3152（max_abs 3.07e-8，A 梯度范数 5.99e-8）；.1 / dA_T-only 的 dk 1.9064；1e-6 / do-only 的 dk 为 ∞（A 严格为 0、B 为 9.77e-4）。
机理：正单分量 key / query 归一化后恒为单位轴，这些 cotangent 下相关梯度**数学上为 0**（落在归一化的零空间），普通范数下绝对残差很小，但纯相对 1e-4 判据被舍入残差支配。所以裁定要针对「**真零 / 近零梯度的基准与量化判据**」，
而不是「拒绝近 eps 行」（后者解决不了同类相消）；下面第 ①、④ 点据此读：④ 的「拒绝近 eps 行」不是充分处置，也不能把 `[eps, 约 1e3·eps]` 当已证实的支持域。

**要 PM 裁的**（原文保留，供对照）：oracle 在「近零真实导数」区（范数 ∈ [eps, 约 1e3·eps]）本身就是相消噪声，kernel 与它逐位「一致」没有意义、与它「不一致」也不说明 kernel 错。裁定要回答：① 这类输入的判据基准（literal FP32 oracle、FP64 稳定 oracle，还是分区间：远离 eps 用 literal FP32、近 eps 用 FP64 / 稳定解析式）；
② 预算的口径（相对 L2 对近零真实导数不适用时用什么，如相对全局梯度范数的绝对判据）；③ 怎么冻结（实现前定死、事后不得放宽，同 GDA-03）；④ 公共入口对近 eps 范数行是拒绝还是声明限制（§7 不静默）。**在裁定写进本规格之前，申领人不要自行扩大预算、排除这些输入或改变归一化公式**（他们也已声明没这么做）。

## 2026-09-23 PM 裁定（生效，不再是「待裁」）

方法论借用 D-PM-51 / D-PM-52 对 KDA 近零门控端点的处理框架（**AGENTS.md §6**），不是照搬它的具体数字——PGDN 这里的判据基准、阈值、口径都要独立定，理由如下逐条给。

**① 判据基准——逐元素分类，不是按输入行整体分类**：对每个梯度输出元素单独判：
- 算它在该输入下的**解析真值**是否严格为零（可从归一化的零空间结构代数验证——正单分量输入在给定 cotangent 下，径向导数分量恒为 0，这是补充 2 里已经证明的机理，不需要重新猜）。
- **严格为零**（或量级不超过 `64 × FP32 ULP × 局部尺度` ——64× 是本任务定的阈值，比 D-PM-52 的 KDA 32× 更宽，因为 PGDN 反向链更深、累积舍入更多，具体数字要在真机 / CPU 实测中反过来核实这条留白够不够，不够就据实改大，改小则要新证据）：归为**披露类**（disclosure-only）；
- 其余：归为**普通类**（ordinary），按原定预算判定。
- 不设"远离 eps 用 A、近 eps 用 B"这种按范数分区的办法——补充 2 已经证明失效区不是一个范数区间，是一个结构性零空间，用范数当代理会漏判（`.5`/`1`/`2` 这类不小的范数照样能落进结构性零空间）。

**② 预算口径**：
- 普通类元素：沿用原定「逐梯度相对 L2 ≤ 1e-4」，但分母/分子只对普通类元素子集求范数，不把披露类元素混进这个比值（混进去会被披露类的相消噪声主导，这正是补充 2 报的现象）。
- 披露类元素：不设相对判据（对着一个应为 0 的量算相对误差没有意义）。报两个绝对量，只记录不设通过阈值：a）kernel 实际输出的绝对值（应接近 0，量级本身就是信息）；b）该元素误差对**整个梯度张量全局范数**的贡献占比 `|误差| / ‖整个梯度张量‖`。

**③ 冻结**：本条裁定（分类规则 + 64× 阈值 + 两套预算口径）随本规格一起冻结，**在 kernel 实现开始前生效，交付时不得放宽**；分类算法本身（"解析真值是否严格为零"的判定代码）也要在 A↔B 校准阶段一次写死、进证据，不是运行时臆断。真机实测如果发现 64× 阈值明显不够（大量普通类元素被误判披露类，或反之），走 `RISK` 报给 PM 由 PM 改，不由 assignee 自行调。

**④ 公共入口**：**不拒绝**近零范数的 q/k 行——这不是硬件缺陷（不同于 A2 的 split-K），是真实输入分布会出现的正常情形，前向 `PK-03` 本身也没有为它设特殊入口限制，拒绝会比"披露"更糟（AGENTS.md §7 的隐藏缺失能力更糟原则同样适用于"该报却不报"）。验收与 evidence 里必须显式列出披露类元素的数量、位置（哪个梯度、哪一行）、判定依据（解析真值算出来是多少）；`board`/`contract` 阶段在存在披露类元素时如实标注（措辞参照 KDA 的 D-PM-52：不写"CPU 正确性通过"，写"数值披露完整，非通过"），不把披露类元素悄悄并入"全部通过"的汇总数字里。

## 范围骨架（PM 在 GDA-03 完成后按其经验补全，下面只是已知的硬约束）

- **域与前向 `PK-03` 逐项一致**，不悄悄扩大：`initial_state` / `initial_A_state` 只接受 None（因此没有 `dh0`、`dA0` 输出）、
  T 是 64 的倍数且 ≤ 4096、`HV%H==0`、`block_dim∈{1,2}`、归一化必须开启。
- **上游梯度有三路**：`do`、`dht`（主 state）、`dA_T`（ATK 的 final_A_state）。三路的各种组合都要覆盖。
- **要求导的东西比 GDN 多**：q/k 的 `F.normalize`（含 `1e-12` 钳位与近零行）、ATK 递推 `A_t = exp(g_atk)·A_{t-1} + beta_atk·k²`
  的反向、有界 squash 的 `M`、**读/写 key 不对称**（`k_read` 与 `k_write` 两条路径对 `k` 的梯度都要计入）；
  `g_atk`、`beta_atk` 是 per-`H` 的，来自组内所有 value head 的梯度要**汇总**，不能复制。
- **预研事实（申领人在 #89 下的 CPU 预研，自述，PM 未独立核实；交付物里仍须自己重做）**：独立 CPU 反向递推对 pin 版 PGDN naive 的自动微分，
  七个输入梯度、三路 cotangent（输出、主 state、ATK state），六个 case（分组比 1/2/4/8、一/两个 chunk、零/极小 q/k、`beta_atk=0`），
  最大相对 L2 **1.0479961e-6**。关键细节：**组内 value-head 的贡献先归约，再进共享的 per-`H` ATK 伴随；final ATK cotangent 每个 `H` 只播种一次**。
- **oracle**：A = 对 pin 住的 `precond_gated_delta_rule` naive 做 CPU FP32 自动微分；B = 独立解析反向；两者先过 FP64 gradcheck。
  **PGDN 的 naive 做归一化、PKDA 的不做**（`pkda_semantics.md` §7），别把两个算子的结论互相套用。
- **内部 kernel 形参名避开 C++ 关键字**：GDA-03 的第一次真机构建栽在形参名 `do`（生成的 aclnn 头文件/cpp 里是 C++ 保留字），改内部形参名 `dout`、公共 ABI 不变才过（申领人自述）。本任务同样有 `do`，别再撞一次。
- **预算与口径同 GDA-03**：FP32 每个梯度相对 L2 ≤ 1e-4，先校准再实现，事后不得放宽；BF16 不在本任务（公共入口显式拒绝 BF16、不 host 加宽，用户 D-PM-35，BF16 kernel 侧另有任务）；逐梯度报数字。
- **真机与同卡测量同 GDA-03**（完整 workload 先跑、`bd=1/2` 逐位相同、三轮三明治如实标注基线、不设速度门槛）。
- 机器与卡归 assignee 自己管理（D-PM-28）。
