# GDN-2 chunk 前向 BF16 原生 kernel：误差地板与预算

> **这份文档在写 kernel 之前定稿**（`docs/pm/bf16-kernel-side.md` 通则 §2、BF-05 的 ASSIGN 第 1 条）。
> 下面的 F 与预算**事后不得放宽**；实测超过预算或超过 3F，先发 `RISK` 再动。

## 口径

BF16 路径的公共 ABI：`q` / `k` / `v` 是 BF16，`o` 是 BF16；`g`、`erase_gate`、`w`、
`initial_state` / `final_state` 仍是 FP32（状态与门控前缀的精度是 kernel 内部选择，通则允许）。
域与 GD2-01 完全一致：B=1、T=1..4096、H∈{1,16}、K=V=128，`B≥2` 由入口显式报错。

两个量，分开报，别混：

- **F（误差地板）** = `relL2( bf16(ref), ref )`，其中 `ref` 是 FP32 参考**喂 BF16 舍入后的输入**跑出来的 `o`。
  这是「把 `o` 存成 BF16」这一步本身带来的误差，**任何正确的 BF16 kernel 都不可能比它更好**。
- **D（ABI 舍入）** = `relL2( ref_on_bf16_inputs, ref_on_fp32_inputs )`。
  这是公共 ABI 改成 BF16 输入引入的偏移，**不是对 kernel 的约束**（两个参考都喂同样的 BF16 输入，
  所以它在比较里抵消），只用来说明「BF16 入口」相对 FP32 入口的量级。

## 实测（CPU，FP32 递推 + BF16 输入舍入模拟器）

- **F = 1.7451e-03**（12 例最差，出在 `t1_h1_small`；其余 11 例落在 1.45e-03 ~ 1.69e-03）。
  落在通则说的 2–4e-3 那个量级偏低的一侧，因为 `o` 的动态范围不大。
- D(o) 2.16e-03 ~ 2.92e-03，D(final_state) 2.14e-03 ~ 2.45e-03 —— 与 F 同量级，
  说明「BF16 输入」和「BF16 输出」各自贡献相当，两者都不是可以忽略的一项。

## 预算（定稿，事后不放宽）

对**参考 A**（pin 住的 fla GDN-2 naive，喂 BF16 舍入后的输入）与**参考 B**（本仓独立 CPU 参考，
同样喂 BF16 舍入后的输入）**各判一次**：

| 输出 | dtype | 预算 | 依据 |
|---|---|---|---|
| `o` | BF16 | 相对 L2 ≤ **5.2354e-03** = min(1e-2, 3F) | 3F 规则；3F 小于 1e-2，取严的那个 |
| `final_state` | FP32 | 相对 L2 ≤ **5.2354e-03** = min(1e-2, 3F) | 同一条规则；它是 FP32 输出、没有存储地板，实测应当远低于此 |

- `max_abs` 与相对 L2 一并报，不单看一个。
- **零预算的量严格相等，不写空洞比较**：`bd` 之间的输出**逐位相同**（不是「在预算内」）；
  去掉 host 转换后 **FP32 路径改前改后逐位相同**。这两条按位判，不用上面的预算。
- 超预算或超 3F：先发 `RISK`，不动阈值、不删 case。
