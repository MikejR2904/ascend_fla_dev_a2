## 这条任务是怎么来的、和 A2-13/A2-14 的边界在哪

A2-12（chunk 前向）、A2-13（chunk 反向）、A2-14（decode）分别资格化了 `kernels/projects/a2/`
下的三个**独立单元**，但都没有碰公共入口——`ascend_fla/ops/kda/chunk.py` 的
`chunk_kda_fwd`/`chunk_kda_fwd_with_caches` 和 `ops/kda/__init__.py` 的 `prepare()`，在真正调用
前都会先过 `require_qualified(device)`：

```python
def require_qualified(soc: str) -> None:
    cap = CAPABILITIES[soc]
    if not cap["qualified"]:
        raise RuntimeError(f"该 SoC 未验收：{soc} —— {cap['evidence']}。...")
```

而 `CAPABILITIES["a2"]["qualified"]` **现在仍是 `False`**（PM 刚核实过，见下面"现状核实"）。
这意味着：哪怕 A2-12/13/14 三个单元各自都测过了，**公共调用链上任何一处——包括
`ascend_fla.layers.kda.KimiDeltaAttention` 这个层——在 A2 真机上现在调一次就报错**，不是因为
代码写错，是因为这个总开关按规矩（A2-12 定的："`qualified` 只有 PM 审过才翻"）还没被谁翻过。

**A2-15 就是去把这件事做完**：在层这一级把 A2-12/13/14 的三个单元接在一起跑通（层已经是
SoC-中立的代码，走的是上面那条公共调用链，不需要新写"A2 专用层"），拿到足够的真机证据后，
**由 PM 在审查 DONE 时翻这个开关**（不是本任务自己翻——`qualified` 的翻转规则没变，见下面
"明确不在范围内"）。
